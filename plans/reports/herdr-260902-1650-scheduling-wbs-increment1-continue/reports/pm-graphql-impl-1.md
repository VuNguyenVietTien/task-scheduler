## 4. Increment 1 GraphQL contract (SDL operations — exact names)

**Queries**
- `project_phases(project_id: ID!, include_archived: Boolean): [ProjectPhaseType!]!` — phase reads with translations
- `resource_members(project_id: ID!, only_assignable: Boolean): [ResourceMemberType!]!`
- `resource_member(resource_member_id: ID!): ResourceMemberType!`
- `project_schedule_projection(project_id: ID!): ProjectScheduleProjection!`
- `import_dry_run(manifest: JSON!): ImportDryRunReport!` — pure deterministic dry run, zero writes

**Mutations**
- `ensure_default_phases(project_id: ID!): Int!`
- `create_project_phase(input: CreateTermInput!): ProjectPhaseType!`
- `update_project_phase_translations(input: UpdateTermTranslationsInput!): ProjectPhaseType!` (order/color/translations)
- `archive_project_phase(project_id: ID!, phase_id: ID!, strategy: ArchiveStrategyInput!): Int!` (reassign_to XOR unphased guard)
- `set_task_taxonomy(task_id: ID!, phase_id: ID, category_id: ID): Boolean!` — task phase/category assignment on the task path (reuses task-1.1 validation; plan resolvers untouched)
- `create_resource_member(input: CreateResourceMemberInput!): ResourceMemberType!`
- `link_resource_member_user(resource_member_id: ID!, user_id: ID!): ResourceMemberType!`
- `classify_resource_member(resource_member_id: ID!, classified_by_resource_member_id: ID!): Boolean!`

**Types**
- `enum ScheduleProjectionSource { CURRENT_TASK_FIELDS }` (sole value — Increment 3 will add `CAPACITY_SCHEDULER`)
- `ProjectScheduleProjection { project_id, source, phase_groups, wbs_rows, totals }`
- `SchedulePhaseGroup { phase_id (nullable), phase_key, is_unphased, task_ids, totals }` — exact display order + explicit `unphased` group LAST (always present, even empty)
- `union ScheduleWbsRow = ScheduleTaskEntry | ScheduleSourceHeading`
- `ScheduleTaskEntry { task_id, title, phase_id, start_date, end_date, effort_hours, progress, depth }`
- `ScheduleSourceHeading { heading_id, source_system, external_id, title, depth }` — **DISTINCT object: NO task_id / NO dates / NO effort / NO progress** (no bar callbacks possible); enforced by contract test on both sides
- `ScheduleTotals { task_count, effort_hours: String!, progress, start_date, end_date }`
- `ImportDryRunReport { source_system, root_external_id, root_title, heading_count, task_count, phase_counts:[DryRunPhaseCount!]!, total_effort_hours: String!, issue_1139: DryRunIssue1139Check!, planned_assignee_count, planned_dependency_count, diagnostics, snapshot_sha256 (pinned name), report_json: JSON }`
- `DryRunIssue1139Check { external_id, effort_hours: String!, assignee_display_name, assignee_linked, wbs_row }`

**Decimal convention:** all effort/effort-hours fields are `String` in 2-decimal display form (`display_effort`: `Decimal::from_f64_retain → format!("{:.2}")` → `7.5f64 = "7.50"`, `0.1+0.2 = "0.30"`, `None/NaN = "0.00"`). Increment 2 migrates the producer to exact `NUMERIC(10,2)`.

**Projection invariants (pure tests):** rollups are ONE flat pass — each real task contributes exactly once to its phase group and to project totals regardless of hierarchy depth (3-level chain → count 3, effort "60.00"); tasks referencing inactive/unknown phases fall into Unphased, never dropped; WBS rows are a flat pre-order traversal mixing source headings and task subtrees with depths; heading/task cycles surface once, never panic; `assemble_forest` (domain) orphan/self-parent → roots contract locked by test.
